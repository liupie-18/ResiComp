# ResiComp 模型设计

本文档深入讲解 ResiComp 模型架构及其组件，用于抗丢失图像压缩。

## 概述

**ResiComp**（抗丢失图像压缩）是一种神经图像编解码器，设计目的是即使在压缩比特流通过不可靠网络（如无线网络）传输时遭遇丢包，也能保持良好的重建质量。

### 核心创新：双功能掩码视觉令牌建模

核心创新是**双功能 Transformer**，同时服务于两个目的：
1. **熵预测**：估计算术编码的概率分布
2. **令牌预测**：预测缺失/掩码令牌以实现错误弹性

这种双重功能使模型既能高效压缩，又能优雅地从丢包中恢复。

### 2. ELIC 编码器-解码器

基于先进的 ELIC（高效学习图像压缩）架构：

#### 分析变换 (g_a)
- **输入**: RGB 图像（3 通道）
- **架构**: 4 个带 GDN（广义除法归一化）的卷积层
- **下采样**: 16×（每层步长为 2）
- **输出**: 192 通道的潜在表示
- **目的**: 将图像转换为紧凑的潜在空间

```python
Conv(3→128, k=5, s=2) → GDN 
  → Conv(128→128, k=5, s=2) → GDN
  → Conv(128→128, k=5, s=2) → GDN
  → Conv(128→192, k=5, s=2)
```

#### 合成变换 (g_s)
- **输入**: 潜在表示（192 通道）
- **架构**: 4 个带逆 GDN 的转置卷积层
- **上采样**: 16×（重建原始图像分辨率）
- **输出**: RGB 图像（3 通道）
- **增强**: 包含残差注意力块以提升质量

```python
Deconv(192→128, k=5, s=2) → iGDN
  → Deconv(128→128, k=5, s=2) → iGDN + 注意力
  → Deconv(128→128, k=5, s=2) → iGDN + 注意力
  → Deconv(128→3, k=5, s=2)
```

### 3. 双功能 Transformer

ResiComp 的核心，实现带双重预测头的掩码视觉令牌建模。

#### 3.1 架构细节

**输入处理**:
- 潜在表示: `y_hat` (B×192×H×W)
- 展平为令牌: (B×L×192) 其中 L = H×W
- 掩码令牌替换为可学习的 `mask_token`

**嵌入**:
```python
x = latent / delta  # 归一化 (delta=5.0)
x = Linear(192 → 768)  # 嵌入到 transformer 维度
```

**Transformer 块** (12 层):
- **类型**: Swin Transformer（移位窗口注意力）
- **维度**: 768
- **注意力头**: 8
- **窗口大小**: 4×4
- **移位策略**: 交替（0 和 window_size//2）
- **MLP 比率**: 4× (768 → 3072 → 768)

**输出头**:

1. **熵参数头**:
   ```python
   Conv(768 → 3072, k=1) → GELU
     → Conv(3072 → 3072, k=1) → GELU
     → Conv(3072 → 192×9, k=1)
   
   输出: 高斯混合模型参数
     - probs: (3×B×192×H×W) - 混合权重
     - means: (3×B×192×H×W) - 分量均值
     - scales: (3×B×192×H×W) - 分量尺度
   ```

2. **预测头**:
   ```python
   Conv(768 → 3072, k=1) → GELU
     → Conv(3072 → 3072, k=1) → GELU
     → Conv(3072 → 192, k=1)
   
   输出: 预测的潜在值 (B×192×H×W)
   ```

#### 3.2 掩码视觉令牌建模

**训练阶段**:
1. 随机掩码: 随机掩码 5%-99% 的令牌
2. 使用掩码输入的前向传播
3. 预测所有令牌的熵参数
4. 预测掩码令牌的值
5. 计算双重损失:
   - 来自熵估计的码率损失
   - 来自预测的失真损失

**推理阶段**（自回归）:
1. 使用特定编码顺序（如 QLDS - 准低差异序列）
2. 顺序编码/解码令牌
3. 每个令牌使用先前解码的令牌作为上下文
4. 熵参数根据可用上下文自适应调整

### 4. 高斯混合模型熵模型

使用 3 分量高斯混合进行灵活的概率建模：

**概率计算**:
```python
p(y) = Σ(i=0 到 2) probs[i] × N(y | means[i], scales[i])
```

其中：
- `probs`: 混合权重（通过 softmax 归一化为 1）
- `N(y | μ, σ)`: 量化值的高斯累积分布
- 截断到 [y-0.5, y+0.5] 用于离散符号

**拉普拉斯平滑**:
```python
p_final = 0.999 × p_GMM + 0.001 × p_Laplace
```
防止零概率破坏算术编码。

**压缩/解压缩**:
- 使用范围编码（通过 `constriction` 库）
- 熵最优压缩
- 基于预测 PMF 的逐符号编码

### 5. 编码顺序策略

自回归编码/解码的不同策略：

#### 5.1 QLDS（准低差异序列）
- **目的**: 空间平衡的令牌顺序
- **算法**: 基于黄金比率 φ = 1.324...
- **优势**: 来自所有方向的良好上下文
- **用途**: 标准压缩的默认选择

#### 5.2 渐进式编码顺序
实现质量可扩展性：
```python
ratio = (step_i / total_steps) ^ beta
tokens_to_encode = floor(L × ratio)
```
- `beta=2.2`: 控制渐进曲线
- 早期步骤: 少量令牌（低质量）
- 后期步骤: 更多令牌（更高质量）

#### 5.3 棋盘格模式
- `checkerboard2`: 2 阶段编码（类似棋盘）
- `checkerboard4`: 4 阶段编码
- 快速但上下文灵活性较低

### 6. 丢包弹性

#### 6.1 包划分

使用基于 QLDS 的顺序将潜在空间划分为包：

```python
# 根据依赖关系调整包大小
packet_size[i] ∝ (num_dependencies[i] / total_packets + 1) ^ beta

# 划分潜在
for i in range(num_packets):
    packet[i] = latents[partition_i]
```

#### 6.2 上下文模式

包之间的不同依赖结构：

**IntraSlice**（无包间依赖）:
```
[P0] [P1] [P2] [P3] ...
  ↓    ↓    ↓    ↓
每个包独立编码
```
- 最大弹性
- 较低压缩效率

**Layered**（顺序依赖）:
```
[P0] → [P1] → [P2] → [P3] ...
```
- P0: 基础层（关键）
- P1: 使用 P0 作为上下文
- P2: 使用 P0, P1 作为上下文，依此类推

**MultiDescription_N**（N-描述编码）:
```
N=2 示例:
[P0] [P1] [P2] [P3] [P4] ...
  ↓     ↓    ↓     ↓
      ↘   ↙      ↘   ↙
  P2 使用 P0   P4 使用 P2
  P3 使用 P1   P5 使用 P3
```
- 平衡弹性和效率
- N 个并行流

#### 6.3 丢包恢复

当包丢失时：

1. **识别接收包**: 检查哪些包到达
2. **验证依赖关系**: 
   - 如果包 P[i] 依赖于 P[j] 且 P[j] 丢失，则标记 P[i] 为不可用
3. **上下文构建**:
   - 构建可用令牌的掩码
4. **令牌预测**:
   - 使用双功能 Transformer
   - 基于接收的令牌预测缺失令牌
5. **重建**:
   - 结合接收和预测的令牌
   - 使用合成变换解码

**示例**:
```
发送: [P0] [P1] [P2] [P3] [P4]
丢失:       X           X
接收: [P0] [P2] [P3]

IntraSlice 模式:
  - 所有接收的包都可用
  - 使用 P0, P2, P3 预测来自 P1 和 P4 的令牌

Layered 模式:
  - P0: 可用（无依赖）
  - P2: 不可用（依赖于丢失的 P1）
  - P3: 不可用（依赖于 P2）
  - 仅使用 P0，预测其余
```

### 7. 网络仿真

#### 三状态马尔可夫模型

模拟真实的无线丢包：

**状态**:
- 状态 1: 良好（无丢失）
- 状态 2: 丢失（包被丢弃）
- 状态 3: 突发丢失恢复

**转移概率**:
```
P(1→2) = P       # 进入丢失状态
P(2→1) = p       # 退出丢失状态
P(2→2) = q       # 继续丢失（突发）
P(3→3) = Q'      # 保持恢复
```

**网络条件**（EP1-EP6）:
- EP1: 0.2% 丢失，突发长度 6.5（轻度）
- EP2: 3.1% 丢失，突发长度 1.6（中度）
- EP3: 6.5% 丢失，突发长度 5.0（中重度）
- EP4: 13.8% 丢失，突发长度 1.7（重度）
- EP5: 21.4% 丢失，突发长度 10.0（非常重）
- EP6: 32.4% 丢失，突发长度 2.7（极端）

## 训练策略

### 双重损失函数

```python
# 主重建损失
L_main = λ × D(x, x_hat)

# 弹性重建损失
L_resilient = λ × α × D(x, x_check)

# 码率损失
L_rate = -log2(likelihoods).mean()

# 组合
L_total = (L_main + L_resilient) / (1 + α) + L_rate
```

其中：
- `D()`: 失真指标（MSE 或 MS-SSIM）
- `λ`: 率失真权衡（如 0.0035）
- `α`: 弹性权重（如 0.1）
- `x_hat`: 来自所有令牌的完整重建
- `x_check`: 来自预测令牌的重建（模拟丢失）

### 训练过程

1. **随机掩码**: 随机掩码 5-99% 的潜在令牌
2. **双重前向传播**: 
   - 预测所有令牌的熵参数
   - 预测掩码令牌的值
3. **损失计算**:
   - 码率: 来自熵估计
   - 失真: 来自完整和预测重建
4. **优化**: Adam 优化器，带预热和步长衰减

### 超参数

- 学习率: 1e-4
- 权重衰减: 0.03
- 梯度裁剪: 1.0
- 批大小: 8-16
- 训练轮数: 8-10
- Lambda 预热: 训练前 10% 使用 10×

## 推理模式

### 1. 标准推理（无丢包）

```python
inference_without_packet_loss(image, step=12, beta=2.2)
```

- 使用 QLDS 顺序的自回归编码
- 完整质量重建
- 输出: x_hat, likelihoods（用于 BPP 计算）

### 2. 渐进式推理

```python
inference_for_progressive_decoding(image, step=64)
```

- 生成 64 个中间重建
- 每步添加更多令牌
- 实现质量可扩展性
- 输出: 每步的 (x_check, likelihoods) 列表

### 3. 丢包推理

```python
inference_with_packet_loss(image, packet_tracer, context_mode)
```

- 模拟有丢失的包传输
- 在 100 次试验中测试弹性
- 变化上下文模式（IntraSlice、Layered、MultiDescription）
- 输出: 平均 PSNR、BPP

### 4. 真实压缩/解压缩

```python
# 压缩
strings = mim.compress(latent, context_mode='qlds')

# 解压缩
latent_hat = mim.decompress(strings, latent.shape, device)
```

- 实际比特流生成
- 用于熵编码的范围编码
- 返回压缩的字节串

## 性能特征

### 率失真权衡

由 `lambda` 控制：
- λ = 0.0017: ~0.15 bpp, ~32 dB PSNR
- λ = 0.0035: ~0.25 bpp, ~34 dB PSNR
- λ = 0.0067: ~0.40 bpp, ~36 dB PSNR

### 弹性 vs. 效率

由上下文模式和 `alpha` 控制：

**Alpha 参数**:
- α = 0.0: 无弹性训练，最佳 R-D 但丢包恢复差
- α = 0.1: 平衡（推荐）
- α = 1.0: 强弹性，轻微 R-D 损失

**上下文模式**:
- IntraSlice: 最佳弹性，~5% 比特率增加
- MultiDescription_2: 良好平衡
- Layered: 最佳压缩，易受早期丢包影响

## 关键设计决策

### 1. 为什么双重功能？

**问题**: 传统编解码器需要单独的纠错码
- 增加开销
- 固定弹性（无法自适应）

**解决方案**: 统一模型既压缩又恢复
- 不需要单独的 FEC
- 基于实际丢失模式的自适应弹性

### 2. 为什么选择 Transformer？

**优势**:
- 长程依赖性提供更好的上下文
- 注意力机制自然处理缺失令牌
- 基于窗口的设计（Swin）降低复杂度

### 3. 为什么选择高斯混合？

**单高斯**: 对复杂潜在分布过于限制
**3 混合**: 
- 捕获多峰分布
- 足够灵活适应各种上下文
- 参数不会太多（3 是实验最优）

### 4. 为什么选择 QLDS 顺序？

**光栅扫描**: 偏向上下文（仅来自左上）
**随机**: 空间相关性差
**QLDS**: 
- 准随机但确定性
- 空间平衡
- 对压缩和弹性都有利

## 与现有技术的比较

### vs. 传统编解码器（JPEG、H.265）
- **ResiComp**: 学习的、自适应的、弹性的
- **传统**: 手工设计、需要单独的 FEC

### vs. 其他学习型编解码器
- **超先验/自回归**: 良好 R-D 但无弹性
- **ResiComp**: 以最小开销添加丢包弹性

### vs. 多描述编码
- **传统 MDC**: 固定描述，高冗余
- **ResiComp**: 灵活、自适应预测、较低开销

## 扩展可能性

1. **视频压缩**: 扩展到时间域
2. **联合信源信道编码**: 端到端信道模型
3. **不等错误保护**: 每包自适应 alpha
4. **实时自适应**: 基于网络反馈调整上下文模式

## 总结

ResiComp 通过以下方式实现抗丢失图像压缩：

1. **双功能 Transformer**: 统一的熵预测和令牌预测
2. **灵活上下文建模**: 针对不同场景的多种依赖结构
3. **高斯混合熵模型**: 准确的概率估计
4. **智能顺序**: QLDS 和渐进式编码顺序
5. **包级设计**: 显式建模基于包的传输

结果是一种编解码器，即使在显著丢包下也能保持良好质量，与传统仅压缩方法相比开销最小。
